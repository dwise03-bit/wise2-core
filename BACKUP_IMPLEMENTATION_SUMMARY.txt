BACKUP STORAGE LAYOUT
================================================================================

Backup Directory Structure:
  /data/wise2/backups/
    ├── daily/              (Last 30 backups)
    │   ├── wise2-full-YYYYMMDD_HHMMSS.tar.gz
    │   ├── wise2-full-YYYYMMDD_HHMMSS.tar.gz.sha256
    │   └── wise2-full-YYYYMMDD_HHMMSS.tar.gz.manifest
    │
    ├── weekly/             (Last 12 backups)
    │   └── wise2-full-YYYYMMDD_HHMMSS.tar.gz
    │
    ├── monthly/            (Last 12 backups)
    │   └── wise2-full-YYYYMMDD_HHMMSS.tar.gz
    │
    ├── postgres/           (Raw SQL dumps)
    │   └── wise2-YYYYMMDD_HHMMSS.sql.gz
    │
    ├── tmp/                (Temporary files during backup)
    │
    └── reports/            (Backup reports)
        └── YYYYMMDD_HHMMSS-backup-report.txt

S3 Storage (Optional):
  s3://wise2-backups/
    └── wise2-backups/
        └── YYYY-MM/
            └── wise2-full-YYYYMMDD_HHMMSS.tar.gz

Logging:
  /var/log/wise2/
    ├── backup-YYYY-MM-DD.log        (Daily log)
    └── backup.log                   (Aggregated)

Configuration:
  /etc/wise2/backup.env              (Settings & credentials)

================================================================================
BACKUP TYPES
================================================================================

Full Backup
  Components: Database + Application files + Logs
  Size: ~500MB - 1GB
  Duration: ~5-10 minutes
  File: wise2-full-YYYYMMDD_HHMMSS.tar.gz
  Includes:
    - PostgreSQL database dump (pg_dump)
    - Application data directory (/data/wise2/app)
    - Application logs (last 30 days)
    - System configuration
  Retention: 30 daily + 12 weekly + 12 monthly

Database-Only Backup
  Components: PostgreSQL database only
  Size: ~100-300MB
  Duration: ~1-2 minutes
  File: wise2-db-YYYYMMDD_HHMMSS.sql.gz
  Uses: Quick backups, point-in-time recovery
  Retention: Same as full backups

Files-Only Backup
  Components: Application data + logs only
  Size: ~300-700MB
  Duration: ~2-5 minutes
  File: wise2-files-YYYYMMDD_HHMMSS.tar.gz
  Uses: Configuration changes, log archival
  Retention: Same as full backups

================================================================================
SCHEDULING
================================================================================

Cron Schedule (Default):
  0 2 * * *     Daily full backup at 02:00 UTC
  0 2 * * 0     Weekly S3 upload (Sunday) at 02:00 UTC
  0 3 * * *     Retention cleanup at 03:00 UTC

File: /etc/cron.d/wise2-backup

systemd Timer (Optional):
  wise2-backup.timer          Daily backup timer
  wise2-backup-s3.timer       Weekly S3 upload timer
  
  Enable with:
    sudo systemctl enable wise2-backup.timer
    sudo systemctl start wise2-backup.timer

================================================================================
RETENTION POLICIES
================================================================================

Daily Backups
  Keep: Last 30 daily backups (30 days)
  Location: /data/wise2/backups/daily/
  Use: Recent restore needs
  
Weekly Backups
  Keep: Last 12 weekly backups (3 months)
  Location: /data/wise2/backups/weekly/
  Use: Medium-term recovery
  Organization: Friday backups auto-moved to weekly
  
Monthly Backups
  Keep: Last 12 monthly backups (12 months)
  Location: /data/wise2/backups/monthly/
  Use: Long-term archival, compliance
  Organization: 1st-of-month backups auto-moved to monthly

Automatic Cleanup:
  - Old backups automatically deleted when count exceeds retention limit
  - Cleanup runs daily at 03:00 UTC
  - Preserves checksums and manifests during cleanup
  - S3 intelligent tiering for cost optimization

Recovery Point Objective (RPO): 24 hours
Recovery Time Objective (RTO): 4 hours

  Usage: du -sh /data/wise2/backups/
  Errors: grep ERROR /var/log/wise2/backup-*.log

RESTORE PROCEDURES
================================================================================

Database Restore
  From SQL dump:
    gunzip < backup.sql.gz | psql -U wise2 -d wise2_prod
  To test database:
    gunzip < backup.sql.gz | psql -U wise2 -d wise2_test
  Time: ~5-10 minutes depending on size

Files Restore
  Dry-run test:
    tar -tzf backup.tar.gz | head -10
  Restore to temp location:
    mkdir /tmp/restore && tar -xzf backup.tar.gz -C /tmp/restore
  Full restore:
    sudo tar -xzf backup.tar.gz -C /
  Time: ~5-15 minutes depending on size

Full System Recovery
  1. Stop services (2 minutes)
  2. Verify backup integrity (1 minute)
  3. Restore database (5-10 minutes)
  4. Restore files (5-15 minutes)
  5. Fix permissions (1 minute)
  6. Start services (2 minutes)
  7. Verify restoration (5 minutes)
  
  Total RTO: ~30 minutes

Emergency Recovery Flowchart: See BACKUP_SETUP.md

================================================================================
BACKUP VERIFICATION
================================================================================

Integrity Checks
  SHA256 checksum: sha256sum -c backup.tar.gz.sha256
  Archive validity: tar -tzf backup.tar.gz > /dev/null
  SQL validity: gunzip -t backup.sql.gz
  Manifest: cat backup.tar.gz.manifest

Restore Testing
  Automated: Script performs dry-run verification on completion
  Manual: Extract to temp location and inspect before production restore
  Frequency: Quarterly (at minimum)
  Documentation: Keep restore test results

Backup Metadata
  Checksum file: BACKUP.tar.gz.sha256 (SHA256)
  Manifest file: BACKUP.tar.gz.manifest (What's in backup)
  Log file: backup-YYYY-MM-DD.log (Backup execution details)

CONFIGURATION MANAGEMENT
================================================================================

Configuration File: /etc/wise2/backup.env
  Permissions: 600 (readable only by owner)
  Owner: wise2:wise2
  Updates: Manual via sudo nano /etc/wise2/backup.env
  Backup: Included in application files backup
  Versioning: Keep in git-ignored directory for secrets

Settings
  Database: DB_NAME, DB_USER, DB_HOST, DB_PORT, DB_PASS
  Paths: BACKUP_ROOT, APP_DATA_DIR, APP_LOGS_DIR, LOG_DIR
  Retention: RETENTION_DAILY, RETENTION_WEEKLY, RETENTION_MONTHLY
  Notifications: NOTIFY_EMAIL, NOTIFY_SLACK, SLACK_WEBHOOK
  S3: S3_ENABLED, S3_BUCKET, S3_REGION, S3_PREFIX

Security Considerations
  - Never hardcode credentials in cron jobs
  - Use .pgpass for PostgreSQL password
  - Store configuration in secure location (/etc/wise2/)
  - Use IAM roles for S3 instead of access keys
  - Rotate AWS credentials every 90 days

SECURITY & COMPLIANCE
================================================================================

Data Protection
  Backups contain sensitive data (database, config, logs)
  Use encrypted storage (S3 SSE-S3)
  Restrict access to backup directories (700 permissions)
  Use secure protocols (HTTPS for S3, TLS for email/Slack)

Access Control
  Backup script runs as 'wise2' user (least privilege)
  Configuration file readable only by owner (mode 600)
  Backup directories readable only by wise2 user (mode 700)
  IAM roles for S3 (no hardcoded credentials)

Audit Trail
  All backups logged to /var/log/wise2/
  Backup operations recorded with timestamp
  Failed backups generate alerts
  Email/Slack notifications for compliance

Compliance
  GDPR: Backups include PII (encrypt in transit/rest)
  HIPAA: Archive backups to Glacier after 90 days (if applicable)
  SOC2: Log all backup operations, test restores quarterly
  HIPAA: Implement backup encryption at rest
  HIPAA: Implement MFA for backup access (if cloud)

Backup Encryption
  In transit: HTTPS to S3, TLS for email/Slack
  At rest: S3 server-side encryption (SSE-S3)
  Optional: Application-level encryption before backup

SUPPORT & TROUBLESHOOTING
================================================================================

Common Issues & Solutions

Backup Script Won't Run
  Cause: Permissions, missing dependencies, config issues
  Solution: See BACKUP_SETUP.md "Troubleshooting"
  Commands: Check permissions, verify config, test database connection

Database Connection Fails
  Cause: Wrong credentials, PostgreSQL not running, firewall
  Solution: Verify DB_PASS, check PostgreSQL status, test connection
  Command: PGPASSWORD=pass psql -h localhost -U wise2 -d wise2_prod -c "SELECT 1;"

Disk Space Issues
  Cause: Backups too large, retention policy not working
  Solution: Increase disk, reduce retention, enable S3 backups
  Command: du -sh /data/wise2/backups/ && df -h /data

Email Notifications Not Working
  Cause: Mail service not configured, wrong email address
  Solution: Configure postfix/sendmail, verify email setting
  Command: echo "test" | mail -s "test" ops@wise2.dev

S3 Upload Fails
  Cause: AWS credentials missing, bucket doesn't exist, permissions
  Solution: Run aws configure, create bucket, check IAM permissions
  Command: aws s3 ls s3://wise2-backups/
